# 새 세션 전환 운영 규칙 검토

- 검토 도구: `review-llm`, 실제 응답 `modelUsage`의 `claude-fable-5-2`, effort `high`. 중앙 기본값을 바꾸지 않고 작업용 설정 복사본으로 실행했다. 최초·수정분 모두 실제 응답 본문과 성공 응답을 확인했다.
- 범위: AGENTS와 세션 전환 운영 절차·Issue #16 작업 기록의 정적 검토. 리뷰어가 앱을 실행하거나 GitHub·증거 파일을 직접 검증한 것은 아니다.
- 최초 지적: 전환 상태의 문서/댓글 분리, 재개 경로의 동시 실행 위험, 승인된 유한 목록의 기준 부재. 이슈 댓글을 전환 기준으로 통일하고 재개 확인 조건·authorization 기록을 추가했다.
- 수정분 지적: 댓글 URL을 인계 문서에 나중에 넣으면 SHA가 바뀌는 순환 참조, 고정 담당자와 다음 세션 담당 승계의 충돌. 전자는 응답 전에 직접 발견해 전환 ID·이슈 URL 사전 기록으로 고쳤고, 후자는 started의 next_thread_id로 담당을 승계하도록 고쳤다. 대기 재조회와 기존 ID 폐기도 보완했다.
- 판정 한계: 마지막 외부 응답에는 문서 차단 지적 2건이 남아 있었고 이를 직접 보완했다. 최종 버전의 외부 재승인으로 표시하지 않는다. 반복 외부 리뷰는 하지 않았다.
- 실행 근거: 실제 A→B→C 합성 시험, 실패 중단·명시적 재개, 입력/인계/결과 해시 재검증은 [증거 JSON](../evidence/native-session-handoff-2026-11-14.json)에 별도로 남겼다. 이 증거는 문서의 GitHub 전환 절차·상시 장애 복구·중복 방지 보장을 증명하지 않는다.
- 검증: 기존 unittest 92개, wheel/sdist 빌드, 로컬 문서 링크·JSON·이전 인계 보존 검사 통과. 마지막 원격 확인은 Issue #16의 다음 새 세션이 수행한다.
