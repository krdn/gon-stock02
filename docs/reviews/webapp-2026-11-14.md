# 웹앱 독립 리뷰

- 실행기: `~/.codex/bin/review-llm`. 중앙 설정 dry-run의 요청 모델은 `claude-opus-5-5`, effort는 `high`였다.
- 최초 전체 변경과 수정분 한 번을 검토했다. 두 실행 모두 exit 0, `is_error=false`, 실제 반환 `modelUsage`는 `claude-opus-5-5`였다. 모델·제공자 대체는 없었다.
- 두 응답 모두 확정된 CRITICAL/HIGH 없음. 모델 의견을 실제 실행 증거나 사용자 승인으로 간주하지 않는다. 패킷·응답 해시는 [증거](../evidence/webapp-2026-11-14.json)에 있다.

수용한 지적은 0가격을 정상 시세/급락처럼 표시하는 문제, 종목 버튼 재생성 시 키보드 포커스 손실, 미적용 날짜와 적용 구간의 혼동, 손상 manifest 상태의 단정이었다. 0가격은 표·CSV에 보존하되 가격 계산에서 제외하고 선을 끊는다. 포커스 복원·적용 구간 안내·알 수 없음 표시를 추가했다.

수정분 리뷰의 LOW도 직접 확인했다. 0가격 사이의 단일 관측은 점으로 표시하고, 실제 장부의 추가 차단 코드를 허용 목록에 포함했다. 반복 status 안내 갱신과 미사용 차트 스타일을 정리했다. 캐시와 종목 Literal 변경은 확인된 성능·동작 문제가 없어 추가하지 않았다. POST 본문 전달의 Starlette 내부 속성 결합은 lock과 회귀 검사로 관리하는 현재 한계다.

리뷰가 조건부로 제시한 두 검증 공백은 결함으로 재현되지 않았다. `main`은 기존부터 `id="main" tabindex="-1"`였고, 브라우저에서 메뉴 이동 뒤 실제 포커스를 확인했다. 장부 렌더러는 제거한 주문별 `reason`을 사용하지 않으며, 실제 OrderService가 만든 합성 주문 1건을 브라우저에서 접수 상태로 표시했다. 실제 스키마의 `amount`는 TEXT NOT NULL이고 가격·metadata는 정규화 문자열/JSON이다.

최종 직접 검사에는 최초 리뷰 이후 보완도 포함한다. 외부 페이지 링크로 HTML 첫 화면을 여는 경우만 허용하고, 데이터 API·POST·iframe의 cross-site 요청은 계속 거절한다. 이 작은 접속 보완은 외부 재리뷰 입력 이후 추가했으며 전용 회귀 검사와 `localhost` 페이지에서 `127.0.0.1` 앱으로의 실제 링크 클릭을 확인했다. 리뷰 반복 호출은 추가하지 않았다.

전체 113개 검사(웹 21개), JavaScript 구문, wheel/sdist 빌드가 통과했다. 합성 주문은 메모리 브로커 stub만 사용했다. 실제 브로커 요청·주문·장부 변경은 없고, 기존 장부의 journal mode는 DELETE다. 외부 WAL 장부의 부수 파일 동작은 미검증이다.
