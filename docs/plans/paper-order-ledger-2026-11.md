# 모의 주문 장부와 대조

[Issue #5](https://github.com/krdn/gon-stock02/issues/5)의 완료 범위는 주문 의도 영속화, 중복 제출 차단, 모의 브로커 조회 대조와 실패 복구다. 전략 자동운용은 별도 단계다.

브로커는 클라이언트의 요청 ID로 중복 제거를 보장하지 않는다. 따라서 SQLite에 제출 직전 상태를 먼저 커밋한다. 같은 의도 ID는 한 번만 전송하고, 응답 불명·프로세스 종료 뒤에는 조회만 한다. 조회에 없다는 이유로 다시 제출하지 않는다.

| 상태 | 의미 | 다음 동작 |
|---|---|---|
| SUBMITTING | 제출 전 기록 완료 | 해당 실행에서만 POST 1회 |
| CANCEL_SUBMITTING/CANCEL_PENDING | 취소 의도 기록/요청 접수 | 재전송 없이 원주문·취소 연결과 잔고 대조 |
| UNKNOWN | 제출/취소 결과 또는 대조 불명 | 신규 진입 차단, 조회·수동 조사 |
| OPEN/PARTIAL | 주문 접수 또는 부분체결 확인 | 조회 또는 전량 잔량 취소 요청 |
| FILLED/CANCELED/REJECTED | 브로커 대조 또는 명시 거부 | 같은 의도 ID 재제출 금지 |

취소 응답은 취소 요청 접수다. 원주문 잔량·체결·취소 수량을 다시 읽기 전에는 재고나 예약을 해제하지 않는다. 체결 수량 감소, 주문 속성 불일치, 외부 주문, 장부와 계좌 보유수량 차이는 실패로 남긴다.

초기 구현은 계좌당 실행 하나, 동시에 미완료 주문 하나로 제한한다. 파일 잠금과 SQLite 원자적 기록을 사용한다. 브로커 호출은 동일 계좌·호스트의 프로세스끼리 1.1초 간격을 공유한다. 다른 호스트·이 프로젝트 밖의 프로그램까지 제한하지는 못한다.

실계좌 주문 경로는 없으며 KRX 모의 지정가만 구현한다. 신규 매수는 위험 계산과 신선한 KRX 시세·계좌 대조를 통과해야 한다. 매도는 이 장부의 실제 체결 보유분을 초과할 수 없다. 기본 주문 설정은 계속 꺼둔다.

2026-11-13 21시 이후 실행이므로 실제 접수·체결·취소 성공은 이번 야간 실행으로 입증하지 않는다. 로컬 실패 재현과 모의 계좌 읽기 대조, 장중 점검 절차를 구분해 기록한다. 가상 체결이나 테스트 응답을 실제 모의 체결로 표시하지 않는다.
