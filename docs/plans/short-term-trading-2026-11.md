# 4종목 단기매매 3단계 계획

상태: 2026-11-13 사용자 답변을 반영한 계획안. 구현·에이전트 가동·모의주문은 아직 실행하지 않았다.
기준 작업: [Issue #1](https://github.com/krdn/gon-stock02/issues/1). 운영 규칙: [WORKFLOW](../WORKFLOW.md).

## 목표와 확정 범위

삼성전자·SK하이닉스·삼성전기·주성엔지니어링을 매일 개장 전에 분석한다. 조건이 성립하면 반복 매매하고, 매수 당일 또는 다음 거래일까지 청산한다. 목표는 거래비용을 차감한 수익과 손실 통제의 균형이다. 수익은 검증 대상이며 보장하지 않는다.

- 사용자는 처음부터 한도 내 한국투자증권 모의 자동매매를 선택했다. 실계좌 전환은 이번 계획에 포함하지 않는다.
- NXT를 연구·매매 범위에 포함한다. 모의환경에서 실제 지원하는 세션·주문·시세 범위는 1단계에서 확인한다.
- gon-stock02 전용 Buzz 채널과 전문가를 새로 구성한다. 기존 gon-stock의 채널·에이전트를 수정하거나 성과를 가져오지 않는다.
- 현재 구독·연결 모델을 우선 사용한다. 추가 유료 모델·데이터 구독은 보류한다.
- 사용자는 모의 계좌·Open API 신청·모의 키가 준비됐다고 답했다. 이 프로젝트에서 인증·시세·주문을 검증한 상태는 아니다.

‘여러 번 매매’는 기회가 여러 번 생길 때 거래한다는 뜻으로 제안한다. 네 종목을 모두 분석하되 모두 보유할 의무는 없다. ‘그래프 전략’은 수치로 재현할 수 있는 차트·가격·거래량 규칙으로 해석한다.

## 1단계 — 운영 기준과 연결 검증

**완료 조건: 어떤 데이터를 어느 시점에 보고, 어떤 한도에서 모의주문을 낼지 고정하고 실제 연결 증거를 확보한다.**

1. 공식 종목 마스터, 거래일·특별 개장일, KRX/NXT 세션, 종목별 NXT 거래 가능 여부를 확인한다.
2. 모의 API의 인증, 잔고, 시세, 주문·취소·체결 확인, 실시간 연결, 호출 제한을 기능별로 검증한다. 실계좌 주문 경로는 차단한다.
3. 일봉·분봉·호가·체결·공시·뉴스의 확보 기간, 지연, 결측, 수정주가, 이용 조건을 기록한다. 발행 시각과 실제 수신 시각을 구분한다.
4. Buzz 전용 채널·전문가를 등록하고 요청 → 실제 모델 응답 → 채널 게시 → 산출물 저장을 한 흐름으로 확인한다.
5. 위험 한도, 보고 시각, 휴일을 넘기는 보유, 재진입·주문 실패 정책을 실행 설정으로 고정한다.

한국투자증권 모의환경에서 NXT 주문·시세를 지원하지 않거나 지원이 불확실하면 해당 실행을 차단한다. 가능한 KRX 모의주문과 NXT 관측 시세 기반 가상 체결을 별도 장부로 관리하는 대안을 제시한다. 후자는 한국투자증권 모의 체결 검증으로 계산하지 않으며, NXT 주문 지원 목표는 미완료로 남긴다. 추가 시세 권한·유료 데이터가 필요하면 비용 보류 조건을 지킨다.

산출물: 데이터/API 지원표, 위험 설정, 전문가 역할 명세, 실제 요청·응답 증거. 권한·데이터가 부족하면 그 범위를 명시하고 다음 단계의 성과 실험에서 제외한다.

## 2단계 — 전략 설계와 과거 구간 검증

**완료 조건: 진입·청산 규칙을 재현하고, 만들 때 쓰지 않은 이후 구간에서 비용 차감 성과를 측정한다.**

- 모든 투자 리서치·전략 제안·반론·최종분석을 Buzz 작업 스레드로 요청하고 원문 출처와 결과를 연결한다. 데이터 수집·수치 계산은 검증 가능한 코드로 수행한다.
- 초기 후보는 2~3개로 제한한다. 시초 범위 돌파, 추세 내 VWAP 눌림, 과도한 변동 후 평균회귀 등을 연구 후보로 비교한다. 현재 수익성이 입증된 전략으로 취급하지 않는다.
- 종목별 상승·횡보·하락 시나리오, 진입 조건·가격대, 손절·익절·추적청산, 재진입 조건, 보유 기한, 매매 금지 조건을 작성한다.
- 시간 순서대로 학습·선정·최종평가 구간을 나눈다. 보유기간이 겹치는 경계는 분리하고, 뉴스·공시도 당시 확보할 수 있었던 정보만 사용한다. 부족한 과거 자료를 현재 정보로 메우지 않는다.
- 수수료·세금·호가 차이·슬리피지·미체결·부분체결을 반영한다. 같은 봉 안에서 진입·손절·익절이 모두 가능하면 유리한 순서를 가정하지 않는다.
- 동일 기간의 현금 보유, 4종목 단순 보유, 단순 규칙과 비교한다. 순수익·최대낙폭·회전율·종목 집중·장세별 성과와 불확실성을 함께 보고한다. 실험한 후보와 탈락 결과도 보존한다.

산출물: 전략 명세와 버전, 데이터 시점 명세, 재현 가능한 백테스트, 종목별 차트와 진입·청산 표시, 모의 운용 후보 또는 보류 판정.

## 3단계 — 모의 자동매매와 개선

**완료 조건: 실제 모의 주문·체결·잔고·손익을 대조하고, 이후의 새로운 구간에서도 위험 한도와 성과 기준을 검증한다.**

- 연결·장애 검증을 통과한 범위에서 모의 자동매매를 시작한다. 주문마다 사람이 승인하는 방식은 사용하지 않는다.
- 초기 검토 기간은 최소 60거래일 및 왕복매매 100건으로 제안한다. 둘을 채워도 통과를 보장하지 않는다. 거래 횟수를 채우기 위한 매매는 하지 않는다.
- 종목·시장·장세·전략별 결과와 거래 간 상관을 확인한다. 비용 차감 평균 손익의 불확실성이 크거나 일부 날짜에만 성과가 집중되면 검증을 연장한다. 손실 전략은 원인 분석 후 중단한다.
- 매일 판단 당시의 입력·전략·주문·체결·손익을 고정 저장한다. 장중 재분석은 새 버전으로 남기며 기존 예측·전략을 덮어쓰지 않는다.
- 개선 후보는 주 단위로 검토한다. 현재 운용 전략과 별도로 같은 이후 구간에서 비교하고, 사전에 정한 성과·낙폭·오류 기준을 통과한 후보만 교체한다. 교체 전 버전과 복귀 조건을 보존한다.
- 실시간 리서치는 뉴스·공시·가격 조건 발생 시 실행한다. 손절·보유 기한·일일 손실 제한은 리서치 완료를 기다리지 않고 규칙으로 처리한다. 신규 정보는 주문 직전 가격·시각·한도를 다시 검사한다.

산출물: 일일 거래장부, 예상/체결 차이, 주간 성과·실패 분석, 전략 변경 이력, 계속 검증/중단/확대 검토 판정. 모의 체결은 실전의 유동성·체결 품질을 보장하지 않는다.

## 초기 위험 한도 제안

아래 수치는 사용자 요청에 따른 보수적인 초깃값이다. 아직 최적화하거나 실행 설정에 적용한 값이 아니다.

| 항목 | 초기 제안 |
|---|---|
| 가상 운용금 | 1,000만 원. 모의 계좌 전체 잔고와 별도로 배정 |
| 거래 방식 | 현금 매수·보유분 매도, 신용·미수·공매도 제외 |
| 보유 규모 | 동시 최대 2종목, 종목당 25%, 총 50% 이내 |
| 1회 계획 손실 | 운용 기준금의 0.25%, 초기 2만 5천 원. 비용·슬리피지 여유 포함 |
| 하루 중단 | 전일 마감 대비 실현+미실현 손익과 비용 합계 -0.75%, 초기 7만 5천 원 |
| 누적 중단 | 초기금 대비 손실 또는 최고 평가자산 대비 낙폭이 3%에 먼저 도달하면 중단 |
| 보유 기한 | 다음 거래일까지 청산. 초기에는 주말·휴일을 넘기는 보유 금지 제안 |
| 재진입 | 종목당 하루 최대 2회 진입 제안. 신규 신호가 있어야 하며 손실 만회를 위한 증액 금지 |

수량은 종목별 투자금 상한과 ‘1주당 손절 거리+예상 비용’으로 계산한 위험 상한 중 작은 값으로 정한다. 한 주도 한도를 충족하지 못하면 거래하지 않는다. 네 종목의 동반 하락 가능성을 반영해 개별 한도 외에 전체 노출을 검사한다.

갭·거래정지·유동성 부족 때문에 실제 손실은 계획 한도를 넘을 수 있다. 한도 도달 시 신규 진입을 차단하고 미체결 매수 취소·보유 위험 축소를 시도한다. API 장애 때 주문을 반복하지 않고 체결 여부를 먼저 조회한다. 확인할 수 없으면 중단·알림 상태를 유지하며 성공으로 기록하지 않는다.

## Buzz 전문가와 하루 흐름

‘상위 0.1%’는 지향하는 품질 수준이다. 검증하지 않은 자격·정확도·수익률을 에이전트 소개에 쓰지 않는다. 출처 정확성, 당시 정보만 사용했는지, 반론의 유효성, 이후 구간 결과, 지연·비용으로 평가한다.

| 역할 | 책임 |
|---|---|
| 삼성전자 담당 | 반도체·사업별 실적·공시·단기 촉매와 반대 근거 |
| SK하이닉스 담당 | 메모리·HBM·고객/공급망·공시와 단기 촉매 |
| 삼성전기 담당 | MLCC·기판·카메라·수요 변화와 단기 촉매 |
| 주성엔지니어링 담당 | 장비·수주·고객 투자·공시와 단기 촉매 |
| 시장 담당 | 해외장·금리·환율·국내 일정과 업종 공통 위험 |
| 차트·수급 담당 | 가격·거래량·호가·변동성으로 검증 가능한 신호 정의 |
| 퀀트 검증 담당 | 데이터 품질·미래정보 유입·비용·과적합·성과 비교 |
| 위험·반론 담당 | 결론의 반대 근거·상관 위험·중단 사유. 매매 거부 가능 |
| 최종전략 담당 | 근거와 이견을 종합해 종목별 매매/관망 계획 발행 |

에이전트 이름은 `ggw-gon-stock02-<role>`을 사용한다. 전용 채널은 `ggw-gon-stock02-research`, `ggw-gon-stock02-strategy`, `ggw-gon-stock02-ops`를 제안한다. 종목별·날짜별 스레드로 연결한다. 각 역할은 먼저 독립 결론을 쓰고 이후 교차 검토한다. 같은 모델에 같은 내용을 반복 질문한 횟수를 독립 증거 수로 계산하지 않는다.

역할 명세에는 입력·허용 도구·출처 기준·결과 형식·반론·불확실성·시간/비용 한도를 둔다. 실제 모델 ID와 반환 모델을 기록한다. 연구 역할은 주문 권한을 갖지 않으며, 실행기는 검증된 전략과 위험 설정만 처리한다. 채널 분리만으로 권한 격리를 보장하지 않고 도구·계정 권한도 확인한다.

일정 초안(KST): **07:40 개장 전 최종 보고 → 08:50 KRX 개장 전 갱신 → 장중 사건별 재분석 → 허용 세션 종료 후 성과 대조 → 주간 후보 평가**. 이는 일반 거래일 제안이며 특별 개장일에 조정한다. NXT 주문이 지원되면 08:00 전 분석을 완료하고, 매매 종료·청산 컷오프는 실제 지원 세션에 맞춰 1단계에서 고정한다.

매일 각 종목 보고서에 기준 시각·출처, 촉매/반론, 가격·거래량 차트, 진입·손절·익절·보유 기한, 수량 상한, 관망 조건, 승인된 전략 버전을 포함한다. 하루 종료 시 모의 계좌의 주문·체결·잔고와 장부를 대조한다.

## 선택 이유와 남은 결정

종합 분석부터 자동 주문까지 한 번에 연결하는 안보다, 운영 연결 → 전략 검증 → 모의 성과 검증으로 나누는 안을 선택한다. 후자는 초기 단계가 더 필요하지만 데이터 오류·판단 오류·주문 오류를 구분할 수 있다. 단계 내 모의 운용은 사용자가 선택한 자동 방식으로 수행한다.

실행 전에 남은 결정은 위험 수치·휴일 보유·재진입 제한의 확정, NXT 모의 지원 범위, 무료로 확보할 과거 자료의 깊이, 현재 구독 모델의 실제 Buzz 실행 가능 여부다. 자료가 부족하면 유료 구매를 자동 실행하지 않고 범위·기간의 대안을 제시한다. 계좌·키는 문서나 Buzz 메시지에 기록하지 않는다.

- [한국투자증권 공식 저장소](https://github.com/koreainvestment/open-trading-api): API 예제와 전략/백테스트 관련 코드가 있다. 이 프로젝트와의 호환·성과는 미검증이다.
- [공식 현금주문 예제](https://github.com/koreainvestment/open-trading-api/blob/main/examples_llm/domestic_stock/order_cash/order_cash.py): `demo` 구분과 KRX 모의주문 예시 확인. 이것만으로 NXT 모의 지원을 단정하지 않는다.
- [공식 실시간 시세 코드](https://github.com/koreainvestment/open-trading-api/blob/main/examples_user/domestic_stock/domestic_stock_functions_ws.py): NXT 실시간호가 구독 기능 확인. 사용자 권한과 모의환경 수신은 미검증이다.
- [NXT 매매제도](https://www.nextrade.co.kr/menu/transactionSys.do): 공식 페이지 검색 결과에서 프리마켓 08:00~08:50 확인. 본문 직접 열기는 403으로 실패했다. 실행 전 실제 거래일 공지를 다시 확인한다.
- [Buzz ACP 문서](https://github.com/block/buzz/blob/main/crates/buzz-acp/README.md): 채널 요청을 에이전트로 전달하는 구조 확인. 설치된 런타임·채널 권한·회신의 실제 동작은 별도로 확인한다.

위 공식 자료 확인은 기술 지원 범위 조사다. 종목 투자 리서치와 전략 수익성 검증은 아직 수행하지 않았다.
