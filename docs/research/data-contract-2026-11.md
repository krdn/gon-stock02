# 데이터 지원·완전성·비용 검증

“데이터 지원·완전성·비용 검증을 이어가줘.”의 결과다. 과거 분봉의 백테스트 사용은 계속 보류한다. 다음 검증 범위는 공식 지원되는 **KRX 모의 당일 분봉의 앞으로 수신할 자료**로 정한다. 수집기 구현·실제 수신 완료를 뜻하지 않는다.

[Issue #11](https://github.com/krdn/gon-stock02/issues/11) · [기계 판정·출처·해시](../evidence/data-contract-2026-11-13.json) · [이전 검사](data-readiness-2026-11.md). 2026-11-13 확인.

## 지원 범위와 정보 가용 시각

다시 받은 [공식 XLSX](https://apiportal.koreainvestment.com/files/download/apiCollection/API_COLLECTION)의 해시는 이전 검사와 같다. 일봉과 당일 분봉은 모의환경 지원이고, 과거 분봉과 휴장일 조회는 미지원이다. 당일 분봉은 `FHKST03010200`, 호출당 최대 30행이며 전일 자료를 제공하지 않는다. [공식 예제](https://github.com/koreainvestment/open-trading-api/blob/main/examples_llm/domestic_stock/inquire_time_itemchartprice/inquire_time_itemchartprice.py)와도 대조했다.

당일 분봉 규격은 미래 시각 요청의 현재값 반환과 최신 배열의 체결량 갱신 특례를 설명한다. 따라서 봉에 적힌 시각만으로 봉 완성이나 신호 이용 가능 시점을 정할 수 없다. 앞으로 수집할 자료는 원래 시각·실제 수신 시각·응답 버전을 함께 보존해야 한다. 최신 미완성 봉은 신호에서 제외하고, 뒤에 받은 응답만으로 확정을 간주하지 않는다. 봉 시각·확정 규칙 확인이 남는다.

기존 92페이지는 모두 11월 13일에 수신한 조회 스냅샷이다. 과거 날짜의 실시간 수신 기록이 아니므로 `historical_available_at=null`이다.

23:56~23:57 KST에 기존 모의 인증 저장소로 공식 지원 당일 조회를 실행했다. 시세 GET 17회 시도 중 16회 성공했고 다음 호출 제한에서 즉시 중단했다. 삼성전자는 391행을 받았고, 기존 과거 조회와 공통인 381행은 모든 정규화 값이 같았다. 추가 10행은 15:20~15:29의 0거래량 응답이다. API별 봉 생성 차이가 있으므로 없는 봉을 임의 생성하거나 서로 다른 행 수를 곧바로 수집 손실로 해석하면 안 된다.

SK하이닉스는 2페이지·60행 원본만 받은 미완료 상태이며 나머지 두 종목은 미실행이다. 원본 16페이지·451행과 삼성전자 정규화 391행을 별도 경로에 보존했다. 기존 자료를 덮어쓰지 않았다. 이번 검사는 장후 같은 공급자의 API 간 대조이며, 장중 수신·4종목 전체·독립 공급자·세션 완전성 검증이 아니다. 주문은 0건이다.

## 완전성과 기업행동

원본 해시와 고유 키를 다시 확인했다. 일봉 976행에서 공급자 락 표시 8건을 확인했다. 원본에는 표시가 있지만 정규화 봉에는 기업행동 필드가 없다. 아래는 공급자 관측이며 독립 공시 검증이 아니다. 명칭은 공식 XLSX의 `국내주식기간별시세(일_주_월_년)` 시트 `flng_cls_code` 설명을 추출한 값이다. `02`는 배당락, `05`는 중간(분기)배당락이다.

| 종목 | 날짜 | 공급자 표시 |
|---|---|---|
| 삼성전자 | 2025-12-29 / 2026-09-29 | 배당락 / 분기배당락 |
| SK하이닉스 | 2025-11-27 / 2026-02-26 / 2026-05-28 / 2026-08-28 | 분기배당락 / 배당락 / 분기배당락 / 분기배당락 |
| 삼성전기 | 2025-12-29 | 배당락 |
| 주성엔지니어링 | 2025-12-29 | 배당락 |

분할비율 `0.00` 976행과 변경 여부 `N` 976행은 공급자 필드 관측이다. 기업행동·거래정지가 없었다는 증거가 아니다. 공시 시각·권리일·현금/수량 조정이 확인될 때까지 해당 사건을 지나는 보유 손익을 계산하지 않는다.

4종목×5일의 분봉 7,617행을 일봉과 다시 대조했다. 20개 구간 모두 거래량이 달랐고, 주성의 세 시각 부재도 그대로였다. 전체 세션·봉 정의가 미확정이므로 차이의 원인을 수집 손실로 판정하지 않았다. 증거 JSON은 20개 구간별 `eligibility=HOLD`, 사유 코드와 세 결측 시각을 기록한다. 결측 시각은 11-09 10:43, 11-11 09:52·09:53이다. 보간하지 않았다.

[KRX 운영 규정](https://regulation.krx.co.kr/contents/RGL/03/03020401/RGL03020401.jsp)은 일반 세션과 시간외 거래를 구분한다. 일반 운영표만으로 과거 날짜별 특별개장·휴일·정지를 확인할 수 없다. 일봉의 공통 미관측 평일 17일도 미분류로 보존했다. 앞으로의 수집도 공식 날짜별 시간표와 정지를 대조한 뒤에만 세션 완전성을 판정해야 한다.

## 비용 근거 정정

**앞서 인용한 편도 0.0142%를 현재 OpenAPI 모의계좌의 확정 요율로 사용할 수 없다.** 동일 [공개 프로그램](https://vts3.koreainvestment.com/js/app_vts_hantoo_bundle.js)의 문맥을 확인하니 세 출현 모두 대주 모의거래 안내였다. 0.0140527%도 세 번 나오며 AI리그와 과거 대회 안내가 섞여 있다. 파일이 최신이라는 사실은 개별 대회의 규정이 현재 계좌에 적용된다는 증거가 아니다. 두 값 중 하나를 선택하지 않고 계좌 요율을 `null`로 둔다.

[국회예산정책처 「2026 대한민국 조세」](https://korea.nabo.go.kr/board/file/down.do?fid=33319156) 인쇄 407·410쪽에서 세율의 적용 구간을 확인했다. 현재 값은 [한국투자증권 세금 안내](https://securities.koreainvestment.com/main/customer/guide/_static/TF04ae010000.jsp)와도 맞는다.

| 법정 적용 구간 | 코스피 매도 부담 | 코스닥 매도 부담 |
|---|---|---|
| 2025-01-01~2025-12-31 | 거래세 0%+농특세 0.15% | 거래세 0.15% |
| 2026-01-01 이후, 이번 확인일까지 | 거래세 0.05%+농특세 0.15% | 거래세 0.20% |

이 표는 공개 법정 기준이다. 모의계좌 적용·차감·거래일과 결제일의 경계 적용을 검증하지 않았다. 2026년 기준을 2025년으로 소급하지 않는다. 기존 2,284원 예시는 특정 요율을 가정한 산술로만 남으며 비용 계약으로 사용하지 않는다. 법령 페이지 직접 조회는 점검 안내로 실패하여 국회예산정책처 원문을 보완 근거로 사용했다.

장중 검증에는 같은 계좌의 프로그램 규정, 주문·체결·장중/장후/결제 비용 내역이 필요하다. 한 번의 왕복만으로 원 단위 처리와 합산 단위를 확정할 수 없다. 소수 원 수수료가 생기는 서로 다른 거래금액과 분할/합산 체결을 대조해야 한다. 표본을 위한 추가 주문은 이 문서로 승인하지 않는다.

수수료·절사/반올림·합산 단위·차감 시점·스프레드·슬리피지를 모두 미확정으로 남겼다. 체결 모형에는 같은 시장의 매수/매도 호가·잔량과 수신 시각이 필요하다. 모르는 값을 0으로 채우지 않고, 수신 이전 또는 같은 미완성 봉에서 신호와 체결을 만들지 않는다. 이 계약은 아직 실행 모형으로 구현하지 않았다.

## 다음 검증

지원되는 앞으로의 KRX 모의 당일 분봉으로 검증 범위를 정했다. Issue #11의 첫 수용 기준에 해당하며 다른 네 기준은 남는다. 과거 분봉 재수집·실계좌 접근·유료 자료 없이 진행한다.

이번 계약은 KRX 자료 검증에 한정한다. 전체 계획의 NXT 가상체결·시세 검증은 이 결과로 충족하지 않는다.

로컬 재현 명령은 `uv run python .local/issue11-contract-20261113/check.py`다. 스크립트·실측 원본은 해당 로컬 경로에 보존했고 해시는 증거 JSON에 있다. 공개 저장소만으로 원본 대조를 재실행할 수는 없다. 호출 중단은 수집 스크립트와 재시도 없는 클라이언트 경로를 확인한 근거이며 패킷 캡처가 아니다. 규격의 봉 특례와 법정 세율은 보존 원문의 수동 확인과 자동 해시 대조를 구분해 기록했다.

다음에는 날짜별 공식 개장·정지와 봉 확정 규칙을 확인하고, 모의 당일 분봉의 수신 기록을 보존한다. 비용 실측은 기존 장중 주문 검증 범위와 연결하되 계좌 적용 규정부터 확인한다. 과거 자료와 비용의 `backtest_ready=false`를 유지한다.

이번 XLSX 전체 해시는 `620315e4…ad983`으로 이전 `193c303a…9ee0`과 달랐다. 보존본과 디코딩한 셀을 비교했을 때 `주식당일분봉조회`·`국내휴장일조회` 두 시트의 셀 값은 모두 같았다. 파일 변경 전체를 검토한 결과는 아니다. 휴장일 API는 여전히 모의 미지원이며 개장일·결제일 여부만 제공하고 개장/폐장 시각 필드는 없다. 실계좌 조회로 보완하지 않았다.

다음 실증은 별도 승인 범위에서 아래 조건을 확보한 뒤 수행한다.

1. 대상 날짜·KRX 시장·세션별 개장/폐장·적용 공지와 확인 시각을 고정한다. 과거 20구간은 이 대조 전까지 HOLD다. 현재 일반 운영표만으로 17일을 자동 분류하지 않는다.
2. 4종목의 날짜별 정지 결과를 보존하고, 정지일은 KIND 공시 등으로 정지·재개 시각을 대조한다. 기업행동 8건의 공시·권리일·조정도 별도 확인한다.
3. 봉 경계·무거래·확정/정정에 대한 공급자 근거를 확보한다. 확인된 개장일에는 [수신 운영](../operations/minute-capture.md)에 따라 새 경로에 분 경계 전후·첫 체결 전후 응답 버전을 보존한다. 그 관측만으로 일반 확정 규칙을 입증하지 않는다.
4. 같은 모의계좌에 적용되는 프로그램·유효일·수수료 규정을 먼저 연결한다. 비용 차감 실측은 기존 장중 검증의 별도 승인 범위에서 거래금액·분할체결·장후/결제를 대조한다. 이 조사로 추가 주문을 승인하지 않는다.

소스 원문은 로컬 임시 경로에만 보존했다. 저장소에는 URL·실제 확인 시각·원문 해시·시트/화면 위치와 판정을 저장했으며, 원문 전체가 들어 있는 재현 패키지는 아니다. 봉 확정·완전성·비용·체결 모형은 계속 미검증이다. 주문 OFF, `strategy_eligible=false`, `backtest_ready=false`를 유지한다.
