# 조회·시세·연구 기반 사용법

2026-11-13 기준 1단계의 조회·연구 경로를 구현했다. **자동매매는 아직 시작하지 않았다.**
실제 관측은 [검증 기록](../evidence/stage1-2026-11-13.json), 지원 제약은 [KIS·NXT 조사](../research/kis-nxt-support-2026-11.md)에 있다.

## 실행

Python 3.12 이상과 `uv`를 사용한다. OS 인증 저장소에는 기존 `service=gon-stock-kis`, `environment=mock/real` 레코드가 있다.
키·계좌를 인수나 파일로 전달하지 않는다. 현재 CLI는 주문 명령을 제공하지 않는다.

```sh
uv sync --locked
uv run gs02 probe --output .local/evidence/kis-probe.json
uv run gs02 feed-probe --venue KRX --seconds 15 --output .local/evidence/krx-feed.json
uv run gs02 feed-probe --venue NXT --seconds 15 --output .local/evidence/nxt-feed.json
uv run python -m unittest discover -s tests -v
uv build
```

`probe`는 모의 인증·잔고·4종목의 KRX/NXT/통합 현재가·당일 분봉을 순서대로 조회한다.
프로브가 시작된 뒤 인증·조회 실패가 있으면 기록을 저장하고 종료코드 1을 반환한다. 실행 전 인증 저장소 접근 실패는 표준 오류에만 남긴다. 주성 NXT 시세 실패를 숨기지 않는다.
계좌값·키·토큰은 결과에 넣지 않으며, 현재가는 거래소 발생 시각이 없으므로 신선도 미검증으로 남긴다.
당일 분봉이 없는 개장 전·휴장일에는 전체 REST 프로브가 실패할 수 있다. 빈 봉·전일 봉을 당일 조회 성공으로 처리하지 않는다.

`feed-probe`는 1~60초만 수신한다. KRX는 모의 키·모의 서버, NXT는 기존 실전 키·실전 시세 서버를 사용한다.
NXT 경로의 HTTP 요청은 접속키 발급(`/oauth2/Approval`) 하나이며, WebSocket은 체결가 구독만 한다. 계좌 조회·주문은 하지 않는다.
현재 NXT 후보는 삼성전자·SK하이닉스·삼성전기다. 주성은 현재 대상이 아니므로 제외했다. 이 고정 목록은 주문 자격표가 아니다.
구독 응답과 실제 체결 메시지를 구분한다. 모든 대상에서 수신 당시 0~5초 이내 데이터가 있어야 프로브가 성공한다.
수신 후에도 가격이 계속 유효한 것은 아니다. 실시간 주문 전에 새 시각·호가·거래상태 검사가 필요하다.
수신 실패 시 종료하고 자동 재연결하지 않는다. 상시 수집·07:40 보고·매매 예약 작업은 설치하지 않았다.
WebSocket은 앱키당 1세션 제한이 있으므로 같은 키를 쓰는 다른 수집기와 동시에 실행하지 않는다.

KIS 공식 Excel의 체결가 응답은 47필드다. 현재 GitHub `ccnl_nxt.py`의 컬럼 목록은 호가 배열이므로 그대로 사용하지 않았다.
원 규격의 날짜·체결 시각·시장별 TR을 검사하고 잘못된 필드 수·숫자·시각을 거부한다.
HTTP 리디렉션과 환경 프록시를 차단한다. 시세 WebSocket은 KIS 문서의 `ws://` 주소를 사용한다.

## 실제 확인 범위

| 경로 | 관측 | 한계 |
|---|---|---|
| 모의 REST | 15:38~15:39 KST, 17개 중 16개 읽기 성공. 4종목 각 30개 분봉(15:01~15:30) | 주성 NXT는 `invalid_market_data`; REST 현재가의 시장·실시간성은 미검증 |
| KRX 모의 WS | 16:02 KST, 4종목 31건(4/11/8/8), 전부 수신 시차 5초 이내 | 모의 시세 연결 관측이며 주문 체결통보와 다름 |
| NXT 실전 시세 WS | 16:02 KST, 3종목 131건(37/73/21), 전부 수신 시차 5초 이내 | 실전 시세 조회만 검증. 모의 NXT 주문 미지원은 그대로 유지 |
| Buzz 연구 | 전용 비공개 채널 3개·역할 신원 9개 등록. quant/risk가 Herdr 패널에서 요청을 읽고 결과 회신 | 두 역할만 실행 검증. 상시 Buzz 구독 실행기는 없음 |

시세 프로브는 모두 장후 구간의 짧은 관측이다. 정규장 혼잡 시 수신량·지연·재연결은 미검증이다.
두 연구 런타임의 세션 기록 모델은 `gpt-6-astra`다. 독립된 작업 범위로 조사했으나 서로 다른 모델 비교는 아니다.
회신의 작성자와 저장 문서 내용 일치를 확인했다. 공급자 응답 모델 메타데이터는 별도로 검증하지 않았다.
나머지 7개 역할의 분석 품질·실제 응답은 아직 검증하지 않았다. 역할 계약은 [COMMON](../../agents/COMMON.md)과 [roles](../../agents/roles.json)에 있다.
연구자의 계좌·주문 접근 금지는 역할 지침이다. 공유 호스트의 OS 권한을 격리한 샌드박스로 검증한 것은 아니다.

## 위험 설정과 한계

[paper.json](../../config/paper.json)은 가상금 1,000만 원, 1회 0.25%, 하루 0.75%, 누적손실/낙폭 3%,
종목당 25%·총 50%·최대 2종목, 종목별 하루 최대 2회 진입을 초기 기준으로 고정한다.
사용자의 자율 진행 위임에 따른 초깃값이며 최적화·성과 검증 결과가 아니다.
운용 상한은 하루 2회다. 위험 연구자의 하루 1회 제안은 2단계 전략 동결 시 채택 여부를 정하며, 더 적게 거래하는 전략을 허용한다.

`assess_entry`는 비용을 포함한 1주 계획손실, 남은 하루/누적/낙폭 여유, 기존 보유·대기 주문의 `reserved_loss_krw`를 검사한다.
수량의 자본 기준은 초기 배정금·전일 마감·현재 평가액 중 최솟값이다. 장중 미실현 이익으로 당일 한도를 늘리지 않는다.
예를 들어 10만 원 진입, 9만 9천 원 손절, 주당 비용 200원이면 1회 계획손실 2만 5천 원 안에서 20주다.
하루 손실 여유가 1,000원뿐이면 같은 조건에서 한 주도 허용하지 않는다.
신선도·시장 확인이 없으면 차단한다. 설정의 `order_submission_enabled=false` 때문에 계산 통과도 주문 허용으로 표시하지 않는다.

입력 자산은 가상 배정금의 비용 반영 평가액이다. `day_open_equity`에는 전일 마감 평가액을 전달하며 세션 변경 때 초기화하지 않는다.
현금·노출·포지션 수·진입 수·예약 손실에는 보유와 미체결 주문을 합산해야 한다.
현재는 계산 함수이며 이를 공급할 영속 장부·원자적 예약·주문 실행기는 없다. 갭·정지 때 손실 상한을 보장하지 않는다.
보유 기한·휴일 금지 설정도 아직 실행기에서 강제하지 않는다.
REST 호출 간격은 클라이언트 하나에만 적용한다. 같은 계좌를 사용하는 여러 프로세스를 함께 실행하면 계좌 전체 제한을 넘을 수 있다.

## 다음 검증

1. 계좌 단위 호출 큐·영속 주문 장부를 연결하고, KRX 모의 주문→부분/전량 체결→취소→잔고 대조와 재시작 복구를 검증한다.
2. KRX/NXT의 별도 시세·가상 체결 장부, 날짜별 시장 자격·휴장·특별 개장·VI 처리를 검증한다. NXT 가상 체결은 KIS 모의 체결로 세지 않는다.
3. 완성봉·호가·당시 공시·비용 데이터를 확보한 뒤 [두 전략 후보와 검증 설계](../research/validation-design-2026-11.md)를 동결한다. 과거 데이터가 부족하면 수집 기간을 늘린다.
4. 개장 전 9역할 연구 흐름과 최종 보고를 검증하고, 정해진 손실·운영 기준을 통과한 범위에서 모의 자동매매를 시작한다.

실계좌 주문과 추가 유료 지출은 범위 밖이다. 1단계 전체·백테스트·수익성·3단계 모의 운용은 미완료다.
