# 웹앱 구현

- 기준: [Issue #41](https://github.com/krdn/gon-stock02/issues/41). 2026-11-14 사용자가 필요한 웹 기능의 판단·구현을 위임했다.
- 기준 main: `d3285557c8a0b9b840b71d6ec4b097eaef625409`. 기존 구성과 Python CI 성공, `gon-workflow ready`·`implementation-ready` 통과 후 시작했다.
- 기술: 기존 Python/uv에 FastAPI·Uvicorn과 정적 HTML/CSS/JavaScript를 연결했다. 별도 Node 서비스·DB·호스팅 없이 기존 엔진과 로컬 자료를 사용한다.
- 기능: 4종목 대시보드, 일봉/1분봉 차트와 날짜 필터·CSV, 수집 무결성·검증 상태, 가정 입력 위험 계산, 기존 모의 주문 장부 조회.
- 경계: 원본·장부·정책을 읽기 전용으로 사용한다. 브로커 요청·주문·수집 실행·백테스트를 제공하지 않는다. #37/#38 실증과 #39 조건부 조사, 기존 HOLD는 유지한다.

## 검증

- 새 웹 검사 21개와 전체 unittest 113개 통과. 필터/CSV, 반복 봉 최신 버전, 파일 해시 불일치, 잘못된 가격/날짜, 경로 이탈·symlink, loopback/Origin, 위험 입력·한도, 실제 주문 모듈의 합성 장부 불변·민감 식별자 제외를 검사했다.
- wheel/sdist 빌드와 JavaScript 구문 검사 통과. 기존 `httpx`를 사용하는 FastAPI TestClient의 deprecation 안내는 남아 있으며 검사 실패는 아니다.
- 실제 로컬 묶음 3개를 조회했다. 대표 수집 묶음의 삼성전자 일봉 244행, 2026-11-13 분봉 날짜 필터·브라우저 CSV 381행을 확인했다.
- 위험 계산 예시(진입 100,000원·손절 99,000원·주당 비용 200원, 정책 가상금)는 20주·계획 손실 24,000원이며 주문 허용 false다. 실제 계좌 비용 실측이 아니다.
- 실제 로컬 장부의 빈 주문 상태를 표시했다. 현재 브로커 계좌 대조를 수행한 결과로 표시하지 않는다.
- 데스크톱·모바일, 빈/손상 자료, 0가격 제외, 키보드 포커스, 적용 날짜 표시, 합성 주문 장부, 외부 링크 접속을 브라우저로 확인했다. [검증 기록](../evidence/webapp-2026-11-14.json) · [독립 리뷰와 지적 처리](../reviews/webapp-2026-11-14.md).
